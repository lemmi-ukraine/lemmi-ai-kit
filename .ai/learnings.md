# Project Learnings

This file is a **lean intake buffer**, not a knowledge store. New lessons are appended here by the
`task-learnings` skill, then **periodically drained** to the agent-facing home where each lesson is
actually useful — so this file normally holds only a handful of not-yet-promoted entries.

**Where the knowledge lives (consult these, not one big flat file):**
- **Universal conventions & anti-patterns** → `AGENTS.md` (always loaded).
- **Cross-cutting patterns** → the relevant skill (project-local `.claude/skills/`; kit skills are plugin-managed).
- **Subsystem conventions & gotchas** → the code-adjacent **module / feature `README.md`**.
  **When you work in a subsystem, consult that subsystem's README** — that is where its
  promoted lessons live.
- **Invariant-guarding gotchas** → a co-located code comment at the exact site it guards.

**How entries are added:** `task-learnings` appends each finding as a `### [YYYY-MM-DD] title` block
under the matching `## Category` header (create the header if absent; use a canonical category —
Architecture Decisions, Common Pitfalls, External Service Quirks, Performance Insights, Pattern
Discoveries, Convention Clarifications). Place each entry under its **topic** category, never at the
file end (a chronological catch-all misleads the consolidator's clustering).

**How it drains:** periodically (`/learning-consolidator`, ~weekly) each accumulated entry is routed
to its home above and removed here.

## Common Pitfalls

### [2026-09-14] Parent Python flags do not reach subprocess interpreters
- **Context**: The flow-mapping publication check found generated bytecode after consumer-side self-probes.
- **Finding**: Invoking the parent with -B does not propagate that flag into subprocesses. Tests inheriting PYTHONDONTWRITEBYTECODE masked the issue even though an adopter using only the documented command could dirty the plugin cache.
- **Impact**: Pass -B to every spawned interpreter and remove the protective environment setting inside installed-copy tests before comparing cache hashes.
- **Category**: pitfall
- **Home**: readme:plugins/core/README.md
- **Enforce-via**: test
- **Verify-at**: tests/test_flow_mapping.py
- **Scope**: durable

### [2026-09-14] A portable code root also controls which file references are project claims
- **Context**: Moving flow validators into an installed Core skill.
- **Finding**: Generalizing the file-reference regex to every slash path introduced new findings for package-cache paths and relative prose references. Deriving its source prefix from the declared code root preserved the consumer contract while supporting independent src/ and lib/ projects.
- **Impact**: Port parser configuration together with root resolution, and compare a real consumer's outputs before and after changing either. Keep bundled probe fixtures independent of that consumer.
- **Category**: pitfall
- **Home**: comment:plugins/core/skills/flow-mapping/scripts/validate_flow_map.py:configure
- **Enforce-via**: test
- **Verify-at**: tests/test_flow_mapping.py
- **Scope**: durable

### [2026-10-27] A guard pinned only by its own table of shapes ships defects that a replay of real recorded input finds
- **Context**: Rebuilding the learnings drain guard's shell arm against a table of 27 shapes.
- **Finding**: The table passed while a replay of 1,216 real commands that name the file found a regular expression that took 11 seconds on a 25 KB line, a `py` word matching inside `.py` file names, and three new false denials of read-only PowerShell. An execution oracle that ran about 1,000 commands in sandboxes then found a dozen shapes the regular expressions could not see, such as a `;` inside a sed script and the word `rm` used as text.
- **Impact**: Before trusting a guard, replay recorded real input through the old and the new version and diff the verdicts, and run the commands for real in a sandbox to measure their effect. A table written from the same mental model as the code shares its blind spots.
- **Category**: pitfall
- **Home**: skill:test-conventions
- **Enforce-via**: prose
- **Verify-at**: tests/test_gate_learnings_drain.py
- **Scope**: durable

### [2026-10-27] Tests that CI collects for the first time can fail on the other operating system
- **Context**: Making CI run the session-retrospective extractor's tests, which lived outside the collected test folder.
- **Finding**: 9 of the extractor's 38 tests failed on Linux though they pass on Windows: the extractor rejects an output folder under /tmp, and pytest's tmp_path is under /tmp on Linux.
- **Impact**: When a change makes CI collect tests that already exist, run them on the CI operating system first (a docker image is enough) and fix them in the same change, or the first pull request goes red for a reason nobody recently touched.
- **Category**: pitfall
- **Home**: comment:plugins/core/skills/session-retrospective/scripts/test_extract_sessions.py:_run
- **Enforce-via**: test
- **Verify-at**: tests/test_skill_script_tests.py
- **Scope**: durable
